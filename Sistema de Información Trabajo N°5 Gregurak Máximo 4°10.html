Arquitectura de Sistemas Informáticos

Conceptos Fundamentales, Modelos y Glosario Técnico. Hecho por Gregurak Máximo y Escudero Santiago 4°10

1. ¿Qué es una arquitectura de sistemas?

Es el plano estructural de un sistema informático. Define cómo se organizan sus componentes, cómo se comunican y qué tecnologías se usan. Una buena arquitectura garantiza escalabilidad, mantenibilidad y rendimiento.

Modelos de Arquitectura

2. Arquitectura Cliente-Servidor

  • Clientes piden recursos; el servidor responde de manera centralizada.
  • Ventajas: Centralización, seguridad reforzada y fácil administración.
  • Desventajas: Posible sobrecarga en el nodo central y representa un punto único de fallo.
Ejemplo: Correo electrónico, navegación web tradicional.

3. Arquitectura de Tres Capas

Divide el sistema de forma limpia y desacoplada en:

  1. Presentación: Interfaz de usuario (Frontend).
  2. Lógica de negocio: Reglas, procesos y transformaciones de datos (Backend).
  3. Datos: Sistema de gestión de bases de datos (Persistencia).

Permite modificar o escalar cada capa de manera independiente sin afectar a las demás.

Ejemplo: Tiendas online (E-commerce).

4. Arquitectura Orientada a Servicios (SOA)

  • Consiste en un conjunto de servicios autónomos y reutilizables que se comunican entre sí mediante protocolos estándar.
  • Promueve fuertemente la interoperabilidad entre sistemas heterogéneos y diferentes tecnologías.
Ejemplo: Sistemas bancarios integrados (validación de clientes, pasarelas de pagos, transferencias).

5. Microservicios

  • La aplicación está formada por una colección de pequeños servicios autónomos, donde cada uno cuenta con su propia base de datos independiente.
  • Ventajas: Escalamiento fino y modular, alta tolerancia a fallos, y permite el trabajo de equipos pequeños y enfocados.
  • Desventajas: Introduce una mayor complejidad operativa y de red.
Ejemplo: Plataformas de streaming y comercio masivo como Netflix, Amazon, Spotify.

6. Computación en la Nube

Se organiza principalmente en tres modelos de servicio:

IaaS (Infraestructura como servicio): Proporciona control total sobre servidores virtuales y recursos de hardware.
Ejemplo: AWS EC2.
PaaS (Plataforma como servicio): Entorno optimizado y enfocado exclusivamente en el desarrollo de código y despliegue rápido.
Ejemplo: Heroku.
SaaS (Software como servicio): Aplicaciones listas para usar directamente desde un navegador web, sin gestionar infraestructura.
Ejemplo: Gmail, Office 365.

7. Arquitectura Distribuida

  • Los componentes están ubicados en diferentes nodos de red físicos o virtuales y se comunican estrictamente mediante el intercambio de mensajes.
  • Destaca por ofrecer una alta disponibilidad, escalabilidad horizontal y gran tolerancia a fallos.
Ejemplo: Motor de búsqueda de Google Search, tecnología blockchain, redes peer-to-peer (P2P).

8. ¿Cómo elegir la arquitectura adecuada?

Requerimiento del Negocio / Técnico Arquitectura Recomendada
Pequeña aplicación de uso interno Cliente-Servidor o 3 capas
Alta necesidad de integración externa con terceros SOA (Orientada a Servicios)
Necesidad de escalabilidad extrema y despliegues independientes Microservicios
Recursos elásticos bajo demanda sin inversión inicial en hardware Cloud (IaaS / PaaS / SaaS)
Alta redundancia, resiliencia y baja latencia global Arquitectura Distribuida

Glosario de Términos Técnicos

Término Significado y Definición
Arquitectura de sistemas Estructura, organización y patrones de interconexión de los componentes de un sistema informático.
Cliente Dispositivo, aplicación o programa que solicita recursos o servicios a un nodo central o servidor.
Servidor Computadora de altas prestaciones o programa dedicado que provee recursos, procesamiento o datos a los clientes.
Punto único de fallo Componente crítico cuya hipotética falla o interrupción provoca la caída completa del sistema.
Escalabilidad Capacidad inherente de un sistema para crecer de forma fluida y manejar un incremento en la carga de trabajo.
Mantenibilidad La facilidad, rapidez y menor coste con la que un sistema software puede ser reparado, corregido o mejorado.
Interoperabilidad Capacidad de distintos sistemas independientes y heterogéneos para intercambiar de manera transparente y usar información.
Protocolo estándar Conjunto de reglas y directrices aceptadas mundialmente para habilitar la comunicación (ej. HTTP, TCP/IP).
Microservicio Servicio de alcance acotado, autónomo, desacoplado y con capacidad de ser desplegado de manera independiente.
Contenedor (Docker) Tecnología de virtualización ligera que empaqueta una aplicación y sus dependencias para ejecutarse de forma aislada.
IaaS Infraestructura como Servicio: modelo de nube donde se alquilan recursos puros de computación como servidores virtuales y almacenamiento.
PaaS Plataforma como Servicio: modelo de nube donde se provee un entorno listo con sistemas operativos y bases de datos para desplegar apps.
SaaS Software como Servicio: aplicaciones completas listas para su consumo final directo a través de internet.
Nodo Cualquier dispositivo activo y direccionable conectado dentro de una red informática (ej. servidor, switch, PC).
Tolerancia a fallos Propiedad que permite a un sistema seguir operando correctamente a un nivel aceptable, incluso ante fallos parciales de hardware o software.
Red peer-to-peer (P2P) Red descentralizada donde todos los nodos actúan simultáneamente como clientes y servidores de información, prescindiendo de un nodo central.
